# invoice-watcher (DB-00004)

כלי למחשב המשרד. עוקב אחרי תיקיית הפלט של מדפסת PDF. חשבשבת מדפיס מקור והעתק
כשני קבצים של עמוד אחד; הכלי מזהה בכל קובץ "מקור"/"העתק" ואת מספר החשבונית,
מצמיד את השניים, מעלה לשרת, ומתייק את המקור ואת ההעתק בתיקיית הלקוחות:
`<לקוח>/<שנה-חודש>/<מספר> <לקוח> מקור <יום-חודש-שנה>.pdf` (ו"העתק"). (קובץ אחד בן שני עמודים — עובד גם.)

השרת משייך לפי מספר החשבונית + "מפתח" (כרטיס הלקוח בחשבשבת). כוונן מול חשבונית
אמיתית (67346, 29/10/2026).

## התקנה
1. מדפסת PDF ששומרת לבד לתיקייה קבועה בלי לשאול שם קובץ (למשל PDF24 עם "שמירה אוטומטית").
   "Microsoft Print to PDF" עובדת, אבל שואלת שם לכל קובץ — פעמיים לכל חשבונית.
2. `npm install` בתיקייה זו.
3. `config.json` (לא להעלות ל-git):
```json
{
  "watchDir":   "C:\\InvoicePrints",
  "sharedRoot": "\\\\SERVER\\Share\\חשבוניות",
  "url":        "https://<האתר>/api/invoice-pdf-upload",
  "token":      "<INVOICE_UPLOAD_TOKEN מ-Vercel>"
}
```
4. `node watcher.js`

## תיקיות
תיקיית ההדפסות (`watchDir`) נשארת ריקה — אין בה תת-תיקיות שאפשר לשמור לתוכן בטעות.
תיקיות העזר נמצאות **לידה** (אפשר לשנות ב-config: `doneDir`, `reviewDir`):
- `לקוחות/` (`sharedRoot`) — המקור וההעתק של כל חשבונית, לפי לקוח וחודש.
- `printCopyTo` ב-config (למשל `"iR-ADV 525 III"`) — ההעתק מודפס לנייר אחרי התיוק, פעם אחת לכל חשבונית, דרך Ghostscript של PDF24 (`gsPath` לשינוי).
- `לבדיקה/` — השרת סירב, הקובץ לא נקרא, או שקובץ חיכה לבן הזוג שלו יותר מ-10 דקות
  (`pairWaitMs`). לא נשלח ללקוח; לטיפול ידני.
- `_הדפסות שטופלו/` — קובצי ההדפסה הגולמיים אחרי שתויקו.
- תיקיית הלקוחות לא זמינה → קובץ ההדפסה נשאר בהדפסות ומנסים שוב בסבב הבא.

## שני מחשבים / הדפסה חוזרת
- הדפסה חוזרת של חשבונית שכבר טופלה (מאותו מחשב או ממחשב אחר) לא נשמרת שוב:
  השרת מחזיר את אותו נתיב ארכיון ומתויקת שוב באותו שם.
- כמה מחשבים מדפיסים: אפשר שכל אחד יריץ את הכלי עם תיקייה משלו, או שכולם ישמרו
  את ה-PDF לתיקייה אחת מסונכרנת (OneDrive) והכלי ירוץ רק על מחשב אחד.

## מדבקות (מרכז ההדפסות, 3/11)
- `labelPrinter` ב-config — למשל `{"host": "10.0.0.253", "port": 9100}` (TSC TE210). בלי זה הכלי לא מדפיס מדבקות.
- הכלי שואל את השרת כל 10 שניות (`labelPollMs`) ב-`/api/print` של אותו אתר כמו `url` (`printUrl` לשינוי — למשל אתר הבדיקות).
- כל משיכה מסמנת בלוח ההדפסות (prints.html) "המחשב במשרד מחובר".
- מדפסת כבויה → העבודה חוזרת לתור (עד 3 ניסיונות). נפל באמצע הדפסה → "לא ידוע" בלוח, ולא מודפס שוב לבד.

## דופק (חדר הסוכנים, 10/11)
- כל דקה (`heartbeatMs`) הכלי שולח לשרת "דופק" לאותה כתובת (`url`) ואותו טוקן: שם המחשב,
  הקבצים שמחכים בתיקיית ההדפסות וכמה זמן, שגיאת ההדפסה האחרונה (אם יש), והגרסה.
- אין מה להגדיר ב-config. דופק שנכשל לא משפיע על החשבוניות — רק שורה ביומן.
- השרת שומר אותו ב-`waMeta/invoiceWatcher/<שם המחשב>` ומריץ ממנו את הבדיקות של הסוכנים
  (קובץ תקוע, שגיאת הדפסה, שליחה שנכשלה, משלוח לשרטט) — מסך "סוכנים" מראה "עובד / לא ענה".
