## 6. נקודות סיכון להקלטה

1. **מעטפת ההקלטה.** `scratchpad/admin-harness.html?p=check-station.html` ו־`?p=workday.html`. המעטפת מסירה את ה־SDK של Firebase ומזריקה את `scratchpad/fake-firebase-admin.js` (שורה 12). **הנתונים שבזיוף היום הם של אדמין** (L9001 ועוד) ולא מתאימים לסרטון. `seed.js` צריך להחליף את `store` במצבים S1 עד S4 מסעיף 1.1.
2. **אין שמירה בין דפים.** הזיוף שומר הכול בזיכרון. מעבר מ־check-station ל־workday מאפס את הכול, ולכן חלק ב מתחיל מ־S2 ולא מהתוצאה של חלק א. צריך לוודא בעריכה שמספרי הדוחות (41, 42) ומספר הפריטים (9) זהים בשני החלקים.
3. **חלון ההדפסה.** `window.open('', '_blank')` נקרא לפני ה־await (`check-station.html:1037`), ואחריו `w.print()` (`:1198`). ב־Puppeteer: (א) לאשר חלונות קופצים, אחרת תופיע ההודעה "⚠️ חלון הדוח נחסם". (ב) לתפוס את הטאב החדש (`browser.on('targetcreated')`) ולצלם אותו לפני ההדפסה. (ג) לעקוף את `print()` בטאב החדש (`page.evaluateOnNewDocument(() => window.print = () => {})`), כי חלון ההדפסה של מערכת ההפעלה לא נכנס להקלטה. את חלון ההדפסה עצמו מוסיפים בעריכה, אם בכלל.
4. **חלון אישור של הדפדפן בטריפלקס.** "קיבלתי את הדוח" בטריפלקס משתמש ב־`confirm()` של הדפדפן (`workday.html:2600`), בניגוד לחיסום שיש לו דיאלוג משלו. Puppeteer צריך `page.on('dialog', d => d.accept())`, והחלון **לא יצולם**. בעריכה מציגים כרטיס שמחקה אותו, עם הטקסט מדויק מ־`:2600`. **[לאשר עם בן]**
5. **אסור שוואטסאפ ייצא.** `confirmResetChisum` קורא ל־`_waSendReadyGrouped` אחרי 1.2 שנ' (`workday.html:2975`), וזה POST ל־`/api/whatsapp-dispatch` (`:2363`). הזיוף מחזיר `{ok:true}` לכל `api/` (`fake-firebase-admin.js:97-98`). **לוודא שהבקשה לא יוצאת לרשת**, ולבדוק אם מופיעה הודעה כמו "לא נשלח" שתיכנס לצילום.
