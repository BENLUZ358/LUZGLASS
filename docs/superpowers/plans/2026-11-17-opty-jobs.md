# OptyWay Optimisations Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an "אופטימיזציות" tab in opty.html. It stores every OptyWay optimisation (sheets, pieces and positions) from the stick, shows the sheets, prints labels in cut order with "לוח i/N" markers, and marks linked order items cut. The cut status shows only in the admin order-details window.

**Architecture:** A new pure module `opty-layout.js` parses `.R01` files, draws sheets, computes the cut day, and builds the label list. opty.html's import also reads `.R01` files and writes `meta/optyJobs/<job>`, then stamps `orders/<id>/items/<k>/optyCut`. The print queue (`api/_print-jobs.js`) keeps three new label fields. `print-labels.js` draws a sheet-marker label.

**Tech Stack:** Vanilla JS (browser + Node), Firebase RTDB compat SDK, Vercel API functions, Node test scripts in `scripts/` (plain `assert`, run with `node`).

**Spec:** `docs/superpowers/specs/2026-11-17-opty-jobs-design.md`

## Global Constraints

- No prod rules change. New data goes under `meta/optyJobs`. `optyCut` sits on order items, exactly where `optyShape` is written today.
- Never write to the stick. Files are only read through `<input type=file>`.
- UI text is plain Hebrew.
- Units: R01 values are hex in 0.1 mm. Total trim in mm = x/20.
- Work day: Ben picks it at import (one picker for all, plus a per-row override). `lgOptyCutDay(File.lastModified)` only supplies the default.
  - Before 12:00 → the same day.
  - 12:00 or later → the next work day (Sun–Thu; Fri/Sat roll to Sun).
- `meta/optyJobs` is its own source of truth for what OptyWay cut. It is kept for unlinked pieces too, and it never overwrites order details.
- Cut status shows ONLY in the admin.html order-details window, never in workday/chisum.
- The import saves only jobs whose cut day falls inside the page's "days" window.
- An item that already has any `optyCut` (including `undone:true`) is never touched by an import.
- Print-queue chunks hold at most 70 labels (`MAX_LABELS`). A chunk never ends on a sheet marker.
- Script version tags: bump `?v=` on every changed script in the pages that load it.

## Review Focus

1. Identical sheets (`H5-6`) must produce one marker plus one set of piece labels for EACH physical sheet. "לוח i/N" counts physical sheets. Test in Task 1.
2. `V<n>` repeats inside a sheet must yield n labels. Test in Task 1, using the M00112-style line.
3. A job whose pieces are not in Pezzi (Pezzi rotated past a month) still saves its sheets with empty info, and still shows. Test in Task 3 (`lgOptyJobRecord` with missing rows).
4. A piece whose shape `.dat` wasn't selected is drawn as a plain rectangle, not an error. Test in Task 1 (`lgOptyLayoutSvg` with no geo).
5. An R01 file time of exactly 12:00, or on Thursday after noon (→ Sunday), gives the right cut day. Test in Task 1.

### Task 1: `opty-layout.js`: parse, cut day, sheet SVG, label list

**Files:**
- Create: `opty-layout.js`
- Test: `scripts/test-opty-layout.js`

**Interfaces:**
- Produces:
  - `lgOptyLayoutParse(text) → Sheet[]`, where `Sheet = { index, count, L, H, trimX, trimY, pieces: [{ order, pos, shape|null, x, y, w, h }] }`. `x`/`y` are from the bottom-left, in mm. `order` is 1-based within the sheet.

  - `lgOptyLayoutSvg(sheet, info, geos) → string`. `info[pos] = { client, name, w, h }` and `geos[shape] = geo` (from `lgOptyShapeParse`).   - `lgOptySheetSeq(sheets) → [{ sheetNo, total, sheet }]`. Physical sheets are expanded by `count`; `total` = the sum of counts.

### Task 3: Job records and cut stamping (pure)

**Files:**
- Modify: `opty-layout.js`
- Test: `scripts/test-opty-layout.js`

**Interfaces:**
- Consumes: `lgOptyLayoutParse` and `lgOptyCutDay` (Task 1). Pezzi rows come from `lgOptyReadTable(...).rows` (opty-paradox.js), with fields `CODCOM POSPZ QTAPZ SAGOMA DIMXPZ DIMYPZ MOLATURA CLIENTE ORDINE COD_MAT_COMP DESCR_MAT_COMP`.
- Produces:
  - `lgOptyJobRecord(job, r01Text, day, pezziRows, nowMs)` returns:
    ```
    { job, day, mat, matName, importedAt: nowMs,
      sheets: Sheet[] (without waste),
      pieces: { [pos]: { client, name, w, h, qty, shape, grind } } }
    ```
    `mat` / `matName` / `pieces` come from the rows of that CODCOM. They are empty when there are none.
  - `lgOptyCutStamps(orders, jobsByNo) → [{ orderId, key, value: { at, job } }]`:
    - `orders` = `[{ id, items: { [key]: item } }]`.
    - An item qualifies when `optyJob` is in `jobsByNo`, its `optyShape` appears among that job's sheet pieces, and it has no `optyCut`.
    - `at` = the job's `day`.
  - `lgOptyCutState(optyCut, todayIso) → null | { label, cut: bool }`:
    - `undone` → null;
    - `at > todayIso` → `{ label: 'לחיתוך dd/mm', cut: false }`;
    - `at == todayIso` → `{ label: 'לחיתוך היום', cut: false }`;
    - `at < todayIso` → `{ label: '✂ נחתך dd/mm', cut: true }`.
