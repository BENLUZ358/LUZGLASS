# החיבור לזגאגי: מה בן צריך לעשות

אפיון: `docs/superpowers/specs/2026-11-01-zgagi-luzglass-link-design.md`

החיבור לא עושה כלום עד שמגדירים את הצעדים האלה. בלי המפתח, כל פנייה מזגאגי נדחית.

## 1. מפתח סודי ב-Vercel (פעם אחת)

1. ב-Vercel ← הפרויקט של לוז גלאס ← **Settings** ← **Environment Variables**.
2. **Add**:
   - Name: `ZGAGI_LINK_TOKEN`
   - Value: מחרוזת ארוכה ואקראית (לפחות 40 תווים). Claude מכין לך פקודה שיוצרת אחת, ואתה מעתיק את התוצאה בעצמך.
   - Environments: קודם רק **Preview** (בדיקות). את **Production** מוסיפים רק כשעוברים לאמיתי.
3. את **אותו ערך** בדיוק מזינים גם בזגאגי (ההוראות שם).
4. **Redeploy**.

את המפתח לא שולחים ל-Claude.

## 2. הלקוח מורשה לוואטסאפ

הודעת "הסקיצות טופלו" עם התמונות יוצאת לטלפון שבכרטיס הלקוח בחשבשבת. ב-Vercel, במשתנה `GREENAPI_ALLOWED_ACCOUNTS`, מוסיפים את מספר הלקוח (למשל `lussglass:14201,lussglass:<המספר החדש>`) ועושים Redeploy.

כל עוד הלקוח לא מורשה, הסקיצה נכנסת כרגיל והפריטים מוכנים. ההודעה פשוט נשארת ב"טופלו וממתינים לעדכון".

## 3. בזגאגי

בקונסולה ← העסק ← "חיבור ללוז גלאס":
- **מספר הלקוח** בחשבשבת
- **איזה מפעל** ברשימה של העסק הוא לוז גלאס

## מה רואים אצלנו

- **בתור הסקיצות, בלשונית הראשונה:** סקיצה עם תג **זגאגי**, הפריטים והמק"טים כבר מולאו. שורה שאין לה מק"ט מסומנת כרגיל, ובוחרים לה מק"ט.
- **"✓ סקיצה טופלה":** הזגג מקבל בוואטסאפ את תמונות הסקיצות.
- **תווית אדומה "עודכן מזגאגי":** הזגג תיקן, והסקיצה הוחלפה. אם ההזמנה כבר נשלחה לחשבשבת, יש רישום בדף **תיקון הזמנות**.
- **"בוטל בזגאגי" בתיקון הזמנות:** הזגג ביטל לפני הייצור.

## מתג לעתיד: דילוג על הלשונית הראשונה

`waMeta/zgagiConfig/skipFirstTab = true` (רק Claude, ורק באישור שלך). מהרגע שהמתג דלוק, סקיצה מזגאגי נכנסת ישר ללשונית השנייה. ההודעה ללקוח מחכה ב"טופלו וממתינים לעדכון".
